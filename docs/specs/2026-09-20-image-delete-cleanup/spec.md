# 图床删除响应与缩略图清理修复

## 背景与问题

图床删除接口在原图和索引已删除后返回 `200` 空响应，Web 通用 API 客户端会将非 `204` 成功响应解析为 JSON，因此将已成功的删除显示为“操作未完成”。对同一图片再次删除时，因记录已移除而返回不存在。

同时，现有删除流程只删除原图与数据库记录，没有删除由该图片生成的私有 WebP 缩略图。

## 目标

- 图片删除成功时返回明确的 `204 No Content`，Web 不再将成功误报为失败。
- 删除原图时同步清理其确定性缩略图缓存。
- 恢复与重试在原图已不存在时仍能完成缩略图和索引清理。

## 非目标

- 不改变图床页面布局、公开链接、上传或对账规则。
- 不清理其他图片的缩略图，不引入全量缓存清理。
- 不变更数据模型或 SMB worker 协议。

## 功能需求

- `IMG-DELETE-FR-001`：`DELETE /api/images/:id` 成功时必须返回 `204 No Content`。
- `IMG-DELETE-FR-002`：删除图片时必须根据现有缩略图指纹规则精确清理对应缓存文件。
- `IMG-DELETE-FR-003`：对应缩略图或原图已不存在时，删除或恢复应视为该对象已清理并继续移除索引。
- `IMG-DELETE-FR-004`：非“不存在”的 SMB 清理失败必须保留 `CLEANUP_PENDING` 以供后台重试。

## 验收条件

- `IMG-DELETE-AC-001`：首次删除成功后 Web 关闭详情并刷新列表，不显示失败提示。
- `IMG-DELETE-AC-002`：已生成缩略图的图片删除后，对应 `.cove-cache/thumbnails/<fingerprint>.webp` 不再存在。
- `IMG-DELETE-AC-003`：原图已被外部删除的待清理记录仍可清理缩略图并移除数据库记录。
- `IMG-DELETE-AC-004`：Server 图床测试、lint、typecheck、build、格式和差异检查通过。
