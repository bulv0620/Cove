# SMB 所见即所得 Markdown 笔记

## 背景与问题

Cove 尚未实现 Notes。此前 roadmap 将 Notes 描述为“Markdown 笔记与 Canvas 画布”，维护者已确认 Canvas 是过时且错误的产品构思；当前目标是提供单一的所见即所得 Markdown 在线编辑能力。

用户希望笔记保持为 NAS 上可直接读取和迁移的普通文件，而不是只能由 Cove 解释的数据库文档。Cove 已有每用户 SMB 绑定、受控的 SMB adapter、图床上传与逐图公开链接，因此 Notes 应复用这些边界，将每用户 home 下的固定目录作为笔记存储，并允许用户在编辑器中粘贴图片后直接上传到现有图床并生成公开 Markdown 图片地址。

SMB 目录也可能被 Files、桌面挂载或其他程序修改。Notes 因此不能假定 Cove 是唯一写入者，也不能直接覆盖一个已被外部改变的文件。保存还必须限制机械硬盘上的小文件写入频率，同时在浏览器异常刷新和 NAS 暂时不可用时保护尚未提交的文本。

## 目标

- 提供以 Markdown 为持久化格式的所见即所得在线编辑器。
- 将当前用户 SMB home 下固定的 `Markdown Notes/` 目录及其中普通 `.md` 文件作为笔记事实源。
- 支持通过真实 SMB 目录和 Markdown 文件完成浏览、新建、编辑、重命名与删除。
- 使用版本检查、同目录临时文件和原子替换安全保存，避免截断文件或静默覆盖外部修改。
- 通过显式保存与浏览器本地恢复草稿兼顾机械硬盘负载、用户预期和异常刷新时的可恢复性。
- 将粘贴或拖入的图片上传到现有图床、立即开启公开访问，并在 Markdown 中写入同源公开地址。
- 保持用户、SMB 凭据、笔记路径和图片权限边界与 Cove 现有身份模型一致。

## 非目标

- 不实现 Canvas、白板、流程图画布或任意自由布局文档。
- 不实现多人实时协作、评论、公开笔记、共享文件夹或跨用户笔记访问。
- 不实现固定的 Markdown 源码编辑、左右分栏预览或 MDX/JSX 执行。
- 不实现双向链接、知识图谱、标签、收藏、全文搜索或历史版本浏览。
- 不同步任意用户选择的 SMB 目录；首版只管理固定 `Markdown Notes/` 根目录。
- 不自动删除从笔记正文移除的图床图片，也不自动清理由撤销编辑产生的未引用图片。
- 不改变图床页面普通上传默认私有、公开链接撤销、缓存或匿名访问规则。
- 不承诺逐字节保留 Markdown 的空白、缩进或等价语法；只保证批准的 Markdown 方言在语义上稳定往返。

## 用户场景

### 打开并编辑 SMB 笔记

已绑定 SMB 且拥有 Notes 页面权限的用户进入 `/notes`，在左侧目录树中逐层展开 `Markdown Notes/` 的目录并打开一篇 `.md` 笔记，直接在排版后的内容中编辑。输入过程不写入 NAS：用户点击保存按钮（或 `Ctrl/Cmd + S`）时，Cove 才安全写回同一个 SMB 文件；未保存就切换到另一篇笔记时，Cove 先询问保存、放弃还是留在原笔记。

### 新建和整理笔记

用户在当前真实 SMB 目录中新建 Markdown 文件或子目录，通过重命名改变文件或目录名称，并在明确确认后删除支持的对象。随后通过 Files 或桌面 SMB 客户端查看时，能看到对应的普通目录和 `.md` 文件。

### 粘贴图片

用户把剪贴板图片粘贴到编辑器或将图片拖入编辑区。Cove 显示上传状态，通过现有图床 API 上传并公开图片；只有在图床确认成功后，编辑器才写入 `![alt](/image/{publicId})`。上传失败不会把临时 Blob、Base64 数据或无效地址写入笔记。

### 处理外部修改

用户打开笔记后，另一个 SMB 客户端修改、替换、移动或删除了该文件。Cove 下次保存时检测到来源版本不一致，保留当前浏览器草稿并明确提示冲突，不静默覆盖 NAS 上的新版本。

### NAS 暂时不可用

编辑期间 SMB 断线或认证失败时，Cove 保留当前用户的本地草稿，显示未保存状态并允许重试。不得把 NAS 故障错误显示为 Cove 登录失效。

## 功能需求

- `NOTE-FR-001`：系统必须在工作空间导航中提供 `/notes` 页面，并使用独立的 Notes 页面及动作权限；无权限用户不得通过直接 API 访问笔记。
- `NOTE-FR-002`：Notes 必须从当前 JWT 用户派生 SMB 绑定和 home，且只允许访问该 home 下固定的 `Markdown Notes/` 根目录；客户端不得指定 NAS 主机、共享、凭据或其他用户。
- `NOTE-FR-003`：首次可写访问时系统必须安全创建 `Markdown Notes/`；未绑定、绑定失效、NAS 离线和权限不足必须显示不同的可恢复状态。
- `NOTE-FR-004`：系统必须把真实 SMB 子目录作为分类，把支持的普通 UTF-8 `.md` 文件作为笔记，并以可逐层展开的目录树呈现（每层按需加载，不预读子树）；支持刷新、在当前选中的目录中新建文件/目录、同目录重命名和明确确认后的删除。
- `NOTE-FR-005`：编辑器必须提供所见即所得 Markdown 编辑，不要求用户在固定源码区和预览区之间切换；持久化结果必须仍是普通 Markdown 文本，而不是 HTML、编辑器 JSON 或私有二进制格式。
- `NOTE-FR-006`：首版 Markdown 方言必须明确限定并至少支持段落、一级至六级标题、粗体、斜体、删除线、链接、引用、有序/无序列表、任务列表、水平线、围栏代码块和 GFM 表格；原始 HTML、MDX、JSX 和可执行内容必须禁用。
- `NOTE-FR-007`：打开笔记时 Server 必须返回正文和不透明来源版本；保存时必须验证来源对象未被外部替换、修改、移动或删除，版本不一致时返回稳定冲突错误并且不得覆盖目标。
- `NOTE-FR-008`：成功保存必须先完整写入同目录、应用保留名称的临时文件并 flush，再通过已验证的原子替换提交；传输、进程或 Server 中断不得把正式 Markdown 文件留在部分写入状态。
- `NOTE-FR-009`：Web 必须提供显式保存（工具栏保存按钮与 `Ctrl/Cmd + S`），串行化同一笔记的保存、合并连续修改、跳过内容未变化的写入，并持续显示未保存、正在保存、已保存、保存失败和版本冲突状态。笔记存在未保存修改时切换到另一篇笔记必须先询问：保存并切换、放弃修改直接切换，或留在当前笔记。
- `NOTE-FR-010`：Web 必须按用户与笔记隔离地保存恢复草稿，作为刷新、崩溃或页面关闭时的兜底；草稿不随输入定时落盘。成功持久化后清除草稿，用户显式放弃修改时删除对应草稿，退出、认证用户变化或强制改密时清理上一身份的草稿。
- `NOTE-FR-011`：输入不得按击键写入 SMB，也不得在后台自动提交；只有显式保存，或在会移动/删除被打开笔记的破坏性操作之前，才向 SMB 提交最新版本。
- `NOTE-FR-012`：粘贴或拖入受支持图片时，Web 必须调用现有图床上传能力并为该次 Notes 上传显式请求公开；图床成功后只把同源 `/image/{publicId}` Markdown 地址写入正文。
- `NOTE-FR-013`：图片上传期间必须显示占位、进度、失败和重试状态；上传失败不得持久化 `blob:`、`data:`、本地文件路径、SMB 路径、访问令牌或未确认的公开地址。
- `NOTE-FR-014`：从正文移除图片引用不得自动撤销或删除图床图片；图片生命周期继续由图床页面管理。
- `NOTE-FR-015`：通过 Files 或其他 SMB 客户端完成的支持范围内变更，必须在用户刷新 Notes 后按实际目录状态呈现；数据库或浏览器缓存不得把已不存在的文件继续显示为有效笔记。
- `NOTE-FR-016`：删除操作必须说明 Cove 不提供撤销，NAS 是否进入回收站取决于 NAS 配置；批量删除、递归目录删除和非空目录删除不在首版范围内。

## 非功能需求

- `NOTE-NFR-001`：单篇笔记必须有可配置大小上限，默认不超过 5 MiB；超限、无效 UTF-8、链接/reparse point、控制字符、路径穿越、UNC、盘符和备用数据流必须在 Server 拒绝。
- `NOTE-NFR-002`：Markdown 编辑器依赖必须通过批准方言的双向往返语料测试；不支持或会丢失语义的输入不得被静默覆盖。
- `NOTE-NFR-003`：保存、重命名和删除必须使用路径边界与 SMB 对象身份校验；只凭文件名或目标存在不得宣称成功。
- `NOTE-NFR-004`：异常退出后的保存状态必须可恢复或可安全判定；清理临时文件时只能使用已登记路径与对象身份，不得按前缀批量删除未知对象。
- `NOTE-NFR-005`：正文、恢复草稿、SMB 密码、公开 grant secret、完整 token 和原始 SMB 响应不得进入日志、审计 metadata 或普通错误响应。
- `NOTE-NFR-006`：编辑页必须支持中英文、深浅主题、键盘操作和移动端基本编辑，并遵循现有页面会话的挂载、关闭和认证清理语义。
- `NOTE-NFR-007`：Notes 列表不得为了显示目录而读取所有 Markdown 正文；首版不得通过高频轮询持续唤醒 SMB，刷新与对账必须由明确用户操作或低频、可停止的策略触发。
- `NOTE-NFR-008`：图片仍由现有图床执行格式解析、大小限制、对象身份校验、公开 grant、匿名限流和撤销；Notes 不得建立绕过图床规则的上传或公开路径。
- `NOTE-NFR-009`：关键创建、保存、重命名、删除、冲突和图片上传编排必须写入脱敏审计或可观测状态，但不得为每次键盘输入写审计。

## 验收条件

- `NOTE-AC-001`：已绑定 SMB 且有权限的用户首次进入 Notes 后看到 `Markdown Notes/`；在 Notes 新建、编辑和重命名文件后，通过 Files 能看到对应普通 `.md` 文件及最终 Markdown 内容。
- `NOTE-AC-002`：没有 SMB 绑定、绑定失效、NAS 离线和无 Notes 权限四种情况分别呈现正确状态，直接 API 越权均被 Server 拒绝。
- `NOTE-AC-003`：批准方言的固定语料经过编辑器导入、无修改导出和编辑后导出，语义与结构保持一致；原始 HTML、MDX 和未知破坏性语法不会被执行或静默覆盖。
- `NOTE-AC-004`：连续输入不产生任何 SMB 写入；只有显式保存（按钮或快捷键）才提交，内容未改变时不产生写入；未保存时切换笔记会先询问，且刷新前尚未成功写入 SMB 的内容可从当前用户的恢复草稿找回。
- `NOTE-AC-005`：保存过程中主动中断浏览器请求、SMB worker 或 Server 后，原正式文件仍完整；恢复流程只确认完整新版本或保留原版本，并精确处理登记的临时对象。
- `NOTE-AC-006`：打开文件后从外部修改、替换、移动和删除目标，四种情况下 Cove 均不静默覆盖，编辑内容仍可复制、重试或另存为新笔记。
- `NOTE-AC-007`：粘贴和拖入多种受支持图片会显示进度，成功后图床记录为公开且 Markdown 含同源公开地址；失败和取消不会向 Markdown 写入临时或敏感地址。
- `NOTE-AC-008`：从 Markdown 删除图片引用不会删除图床图片，图床撤销或删除图片后继续遵循现有不可用行为。
- `NOTE-AC-009`：375、768、1440px 下完成基本浏览与编辑；深浅主题、中文输入法、Tab/Shift+Tab、工具栏可访问名称和页面会话切换通过验证。
- `NOTE-AC-010`：Web 与 Server 相关单元/契约测试、权限失败路径、编辑器往返测试、SMB 故障注入、lint、typecheck、build、格式和差异检查通过。
