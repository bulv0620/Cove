# 页面会话标签与页面状态保留

## 背景与问题

当前 Web 在左侧导航与浏览器 URL 之间使用单活动路由，`DashboardLayout` 的主内容区只渲染当前路由的一个 `Outlet`。用户从 Files、用户、角色等页面切换到另一项功能时，原页面组件会卸载；再次进入会重新创建组件，因此页面内搜索、筛选、排序、选择、滚动位置、尚未提交的输入和弹窗状态可能回到初始值。React Query 当前可以复用部分服务端数据，但不能保留这些组件内的交互状态。

用户希望在截图标出的顶部栏与主内容区之间增加常见管理系统式的页面会话标签。打开的功能可以并存，标签切换时保留页面现场，只有关闭相应标签时才释放该页面会话并在下次打开时从初始状态开始。

本 Spec 已于 2026-09-18 完成实施与验收；稳定行为已同步到产品、架构和行为文档。

## 术语与生命周期

- **页面会话**：一个可访问顶级功能路由在当前已登录 Web 运行周期内对应的、保持挂载的页面组件实例。
- **页面会话标签**：用于显示、激活和关闭页面会话的顶部标签，不等同于浏览器自身的标签页。
- **页面状态**：页面组件及其子组件的本地 React/DOM 交互状态，例如筛选、排序、选择、滚动位置、未提交输入和弹窗开关。
- **共享数据缓存**：React Query 等全局数据缓存。它继续遵循服务端数据的新鲜度、失效和权限规则，不因页面保持挂载而变成永久快照。
- **运行周期**：从一次应用加载并完成身份恢复开始，到硬刷新、关闭浏览器页面、退出登录、401 会话失效或进入强制改密边界为止。运行周期结束等价于释放全部页面会话，不承诺跨刷新恢复任意页面状态。

## 目标

- 在应用顶部栏下方提供清晰、可访问、响应式的页面会话标签栏。
- 在同一已登录运行周期内切换功能时保留各页面的交互现场，避免每次返回都重新开始。
- 关闭标签时可靠卸载该页面实例，使再次打开时获得新的页面状态。
- 保持 URL、浏览器前进/后退、直接访问、权限路由和左侧导航的既有语义。
- 在页面保持挂载的同时隔离非活动页面的焦点、弹窗和可访问性树，避免隐藏页面继续干扰当前操作。

## 非目标

- 跨浏览器硬刷新、浏览器关闭重开、设备切换或重新登录持久化任意页面状态。
- 为同一顶级功能打开多个实例，或把 Files 中每个目录、每条用户记录等子状态分别建成标签。
- 新增 Server API、数据库表或服务端页面会话。
- 冻结服务端数据、绕过 React Query 失效/刷新、离线保存数据或保证后台数据永不变化。
- 标签拖拽排序、用户自定义固定标签、最近关闭恢复、右键菜单、“关闭其他/关闭左侧/关闭右侧”等批量管理。
- 为所有现有表单新增通用的未保存更改检测或关闭确认。若页面已有关闭保护，页面会话关闭必须尊重该保护；否则显式关闭标签会丢弃未提交的本地状态。
- 通过关闭标签取消已经提交到 Server 的操作或全局文件传输；重新打开页面时以服务端事实和全局传输状态为准。

## 用户场景

### 在多个功能之间切换

用户在 Files 中进入某个目录、调整排序并滚动到列表中部，随后从左侧导航打开用户管理。标签栏同时显示 Files 和用户；返回 Files 标签时目录、排序和滚动位置保持不变，且不会为了恢复页面现场重新创建 Files 页面。

### 关闭并重新打开功能

用户关闭用户管理标签。对应页面实例被卸载；之后从左侧导航再次打开用户管理时，搜索、选择和未提交表单均从页面定义的初始状态开始。

### 使用 URL 与浏览器历史

用户直接访问 `/images`，系统创建并激活图床标签。用户通过浏览器后退/前进进入已打开功能时，系统激活已有标签；历史导航进入已关闭但仍有权限的功能时，创建一个新的页面会话。

### 标签较多或窗口较窄

标签总宽度超过可用空间时，标签栏保持单行并提供可操作的横向浏览方式；激活标签始终滚动到可见区域。小屏不会因标签栏产生整页横向溢出。

### 身份或权限发生变化

用户退出、会话收到 401、被要求强制改密或身份切换时，全部页面会话及私有数据缓存被清除。权限刷新后不可再访问的页面标签被立即关闭，前端隐藏不能替代 Server 授权。

## 功能需求

- `PAGE-TABS-FR-001`：受保护工作台必须在现有 64px 顶部栏下方、主内容区上方显示一条页面会话标签栏；标签栏属于应用壳层，在所有已实现的工作台功能中位置一致，不在登录页和强制改密页显示。
- `PAGE-TABS-FR-002`：每个导航注册项必须拥有稳定的 `routeId`、路径、翻译键、图标和页面组件引用。左侧导航、直接 URL 或浏览器历史首次进入有权限的路由时，系统必须创建并激活一个页面会话；再次进入相同 `routeId` 必须复用并激活已有会话，不得创建重复标签或页面实例。
- `PAGE-TABS-FR-003`：激活标签必须更新浏览器 URL、顶部面包屑和左侧导航高亮。直接 URL、浏览器前进/后退以及应用内导航也必须反向同步活动标签；进入已关闭的合法路由时必须创建新的空白页面会话。未知路径继续进入 Not Found，不能创建无效标签。
- `PAGE-TABS-FR-004`：非活动页面会话必须保持同一个组件实例挂载，使本地组件状态、输入值、筛选/排序、选择、页内导航和滚动位置在标签切换后恢复。实现不得通过序列化任意组件状态到 `localStorage` 冒充页面保活。
- `PAGE-TABS-FR-005`：页面保活不得改变共享数据缓存的正确性。页面查询仍可因显式刷新、成功 mutation、既有失效规则、重新连接或权限变化而更新；返回标签时允许看到更新后的服务端数据，但页面交互状态应在数据仍有效时保留，并在对象已不存在时安全清理无效选择。
- `PAGE-TABS-FR-006`：每个页面会话标签（包括 Dashboard）必须有明确的关闭控件。关闭非活动标签不得改变当前路由；关闭活动标签必须卸载页面并使用浏览器 history `replace` 激活最近使用的剩余标签。之后通过历史或导航重新进入该路由时必须创建全新页面状态。
- `PAGE-TABS-FR-007`：Dashboard `/` 必须作为默认会话。首次进入工作台根路由时只打开 Dashboard；直接进入其他合法路由时打开 Dashboard 和目标标签并激活目标标签。Dashboard 可以像其他会话一样关闭；它关闭后只要仍有其他会话就保持关闭。当最后一个页面会话被关闭时，系统必须立即创建并激活一个全新的 Dashboard 会话，并使用 history `replace` 将 URL 设为 `/`，保证标签栏和主内容区永不为空。
- `PAGE-TABS-FR-008`：每个标签必须显示与左侧导航一致的图标和本地化标题，并以不只依赖颜色的方式区分活动状态。标题过长时可以省略显示，但必须提供可访问的完整名称。标签栏必须保持单行；溢出时提供前后滚动控件和触控板/触摸横向滚动，激活项必须自动进入可见范围，不能静默裁掉不可访问的标签。
- `PAGE-TABS-FR-009`：标签栏必须适配 375、768、1024 和 1440px 视口及浅色/深色主题。它不得覆盖主内容；Files 页面可用高度必须扣除顶部栏和标签栏，其他页面既有最大宽度与内容内边距不得被破坏。
- `PAGE-TABS-FR-010`：标签栏必须实现可访问的 `tablist`/`tab`/`tabpanel` 关系、活动/禁用状态和可见焦点。键盘必须支持 Tab 进入标签栏、左右方向键移动焦点、Home/End 跳转、Enter/Space 激活，以及 Delete 关闭当前可关闭标签；关闭按钮与溢出按钮必须有中英文可访问名称，触摸布局的交互目标至少为 44×44 CSS px。
- `PAGE-TABS-FR-011`：非活动页面必须从布局、键盘焦点顺序和可访问性树中隔离，但不能卸载。页面内通过 portal 渲染的 Modal/Popover 等浮层在会话非活动时必须停止显示、停止焦点陷阱和 body scroll lock；重新激活时可以根据保留的页面状态恢复显示。后台页面不得抢焦点、响应仅属于活动页的快捷键或覆盖当前页面。
- `PAGE-TABS-FR-012`：页面会话状态必须绑定当前认证主体。退出登录、API 401、进入强制改密、认证用户 ID 改变时必须同步卸载全部页面会话并清除上一主体的私有 Query 缓存；恢复工作台时重新从概览和当前合法路由开始，不能短暂显示上一用户的页面或数据。
- `PAGE-TABS-FR-013`：当前用户权限集合更新后，所有失去页面权限的会话必须立即卸载。若活动会话被移除，系统必须使用 `replace` 导航到最近使用且仍有权限的标签，否则回到概览；Server 端权限校验保持不变。
- `PAGE-TABS-FR-014`：语言或主题切换必须即时更新所有标签的标题和视觉状态，不得重建页面会话。当前可访问路由集合内不得因内存压力、时间或标签数量自动淘汰后台会话；未来若引入大量或动态路由，必须通过新 Spec 定义上限和用户可见的淘汰规则。

## 非功能需求

- `PAGE-TABS-NFR-001`：页面会话完全位于 Web 边界，不新增 API、数据库数据或敏感持久化。存储中不得出现表单草稿、页面 DOM 快照、SMB 路径内容或上一用户的会话状态。
- `PAGE-TABS-NFR-002`：切换到已打开标签不得依赖重新挂载页面或等待新的网络请求才能显示既有页面现场；标签切换、关闭和溢出滚动必须避免可见布局抖动。动画如有使用应为 150–300ms，并尊重 `prefers-reduced-motion`。
- `PAGE-TABS-NFR-003`：每个 `routeId` 在同一认证主体下最多存在一个挂载实例。非活动页面不得启动由标签系统额外引入的轮询、重复订阅或重复请求；已有页面后台任务必须按既有业务语义运行或通过活动状态显式暂停。
- `PAGE-TABS-NFR-004`：标签、关闭与溢出控件在浅色和深色主题下必须满足可读性与焦点对比要求；活动状态不能只使用颜色表达，图标继续使用项目已有 Lucide 风格，不使用 emoji 充当结构图标。
- `PAGE-TABS-NFR-005`：实现必须保持 React Router 深链接与权限守卫为导航事实源，不得建立与 URL 相互独立、可能绕过路由授权的第二套路由系统。
- `PAGE-TABS-NFR-006`：Web 变更必须通过 lint、typecheck、生产 build、关键交互自动化，以及 375/768/1024/1440px、键盘、浅色/深色和 reduced-motion 的人工或截图验证。

## 验收条件

- `PAGE-TABS-AC-001`（FR-001/002/007）：登录后根路由只显示一个默认 Dashboard 标签；依次打开 Files、用户和角色后共有四个不重复且可关闭的标签，重复点击任一左侧入口只激活原标签，不增加标签或页面实例。
- `PAGE-TABS-AC-002`（FR-004/005）：在 Files 设置目录、搜索/排序、选择和滚动位置，在用户页设置搜索并打开编辑状态，多次切换后各自现场保持；服务端数据被 mutation 正确失效后可以更新，页面不会为了“缓存”展示已经删除对象为仍有效。
- `PAGE-TABS-AC-003`（FR-006/007）：关闭非活动标签不改变当前页面；关闭活动标签按最近使用顺序回退且 URL 使用 replace 同步；重新打开已关闭页面时页面本地状态为初始值。Dashboard 在还有其他会话时可以关闭且不会自动重开；关闭最后一个会话后立即出现一个全新的活动 Dashboard，会话数为一且 URL 为 `/`。
- `PAGE-TABS-AC-004`（FR-003）：直接访问 `/images` 得到概览与活动图床标签；浏览器前进/后退可在已有标签间切换，回到已关闭路由时创建新会话；地址、面包屑、侧栏和标签活动态始终一致，未知 URL 不创建标签。
- `PAGE-TABS-AC-005`（FR-008/009）：在 375、768、1024、1440px 打开所有当前可访问页面后，标签栏单行可滚动、活动项可见且页面无整页横向溢出；Files 列表底部和状态栏不被新标签栏遮挡，浅色/深色布局均无跳动。
- `PAGE-TABS-AC-006`（FR-010/011、NFR-004）：仅用键盘可以遍历、激活和关闭标签，焦点环可见且读屏语义包含标题、选中状态和关闭名称；非活动页面元素不可聚焦或被读屏访问，其打开的 portal 浮层不显示、不锁定 body 且不抢焦点，返回后状态仍可恢复。
- `PAGE-TABS-AC-007`（FR-012/013、NFR-001/005）：打开含私有数据的多个页面后退出或模拟 401，确认所有页面卸载、私有 Query 缓存清空且登录页无旧内容闪现；以另一用户登录只打开其合法页面。撤销活动页权限后标签立即移除并安全回退，直接 URL 仍受权限守卫限制。
- `PAGE-TABS-AC-008`（FR-014）：切换中英文和深浅主题时标签文案与样式即时更新，已打开页面状态不重置；当前六个顶级路由全部打开并反复切换时，每个 routeId 只有一个挂载实例且没有自动淘汰。
- `PAGE-TABS-AC-009`（生命周期、非目标）：硬刷新或关闭浏览器页面后重新加载，任意未提交页面状态不恢复；身份恢复完成后仅依据当前 URL 创建本轮的概览与目标会话。该行为必须在实现说明和长期行为文档中明确，不得声称跨刷新保活。
- `PAGE-TABS-AC-010`（NFR-002/003/006）：自动化证明已打开标签切换不触发页面 mount 初始化或因标签系统产生重复请求；全仓 format/lint/typecheck/build 与关键导航测试通过，并记录响应式、键盘、主题及 reduced-motion 验证证据。

## 开放问题

无。进入批准前，维护者需确认本 Spec 采用以下边界：Dashboard 是默认但可关闭的会话、关闭最后一个会话时自动创建全新 Dashboard、同一路由单实例、关闭时不新增通用未保存确认，以及页面状态不跨硬刷新/重新登录持久化。
