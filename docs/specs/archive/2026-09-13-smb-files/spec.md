# Files SMB 个人文件管理

## 归档说明

维护者于 2026-09-14 确认当前内容验收通过并要求归档。Spec 保留 `Completed` 状态；Docker 完整运行验收仍按维护者先前指令延期，未将该延期项目改写为已验证。稳定行为见 [`../../../behavior/files.md`](../../../behavior/files.md)，部署与密钥说明见 [`../../../operations/files.md`](../../../operations/files.md)。

## 背景与事实

当前 Infrastructure → Files 只有导航占位，没有路由、文件接口或 SMB 适配器；用户管理、JWT、RBAC 和审计基础已经存在。Server/Compose 共用 `apps/server/.env`，Compose 必须显式向 Server 注入新增变量。以上为立项时事实；本次实现与验证已完成，当前行为见 `docs/behavior/files.md`。

## 目标与范围

将 Files 建成面向个人 NAS home 的 Web 文件浏览器：管理员在用户管理中绑定该用户的 SMB 账号，用户登录 Cove 后以绑定的 SMB 身份浏览、上传、下载自己的文件。交互接近 Windows 文件资源管理器，同时沿用现有 Cove 视觉体系。

第一期必须完整交付配置、绑定、个人目录隔离、目录导航、当前目录筛选/排序、多文件上传队列、单文件下载、新建文件夹、异常恢复及部署验证。新建文件夹用于完成上传整理闭环。

## 非目标

- 不在本期增加覆盖已有文件、跨目录移动、复制或应用级回收站；这些属于后续可单独批准的写入能力。
- 不增加目录上传、文件夹打包下载、多文件批量下载、跨目录全文搜索、缩略图、媒体播放、在线编辑、分享链接、离线同步或跨刷新续传。
- 不自动创建 NAS 账号、不同步 Cove 登录密码、不提供 NAS 管理员代读所有用户文件的功能。
- 不在浏览器直接连接 SMB，不以统一 NAS 管理员凭据挂载整个 homes，不引入多 NAS 或每用户自定义服务器/共享路径。

## 用户场景

1. 部署者在 Server env 设置 NAS 地址、个人共享名和凭据加密密钥，重启 Server 后 Files 可用；未启用时不影响身份管理。
2. 有绑定权限的管理员打开用户管理，在目标用户的操作列点击独立“SMB 账号”按钮，输入 NAS 用户名和密码，测试成功并保存。用户进入 Files 看到自己的 home。
3. 未绑定用户进入 Files 看到绑定引导；无绑定管理权限时提示联系管理员，不能读取目录内容。
4. 用户进入 `Documents`，拖入多个文件，看到每个上传进度；完成后刷新当前目录，选择文件下载。
5. NAS 改密或断网后显示可区分的失败状态。更新绑定测试失败保留原绑定，恢复后可重试。

## 功能需求

- `FILES-FR-001`：系统必须从 Server env 读取唯一 NAS 目标、端口、共享、可选 domain 和 SMB 安全策略；用户输入不得改变目标主机或根目录。Docker 使用同一变量命名。
- `FILES-FR-002`：每个 Cove 用户最多有一个 SMB 绑定；具备用户页面与独立绑定管理权限的管理员可以通过用户列表操作区中的独立“SMB 账号”按钮和弹窗，查看脱敏状态、测试、保存/更新和解绑。SMB 维护不得嵌入普通用户编辑弹窗。密码必须只写，不回显；保存前必须重新验证登录和个人根目录可读，失败保留旧值。连接测试成功与失败必须同时使用状态文字、图标和可区分的语义颜色反馈。
- `FILES-FR-003`：Files 仅使用当前登录用户绑定；必须同时满足有效会话、无需强制改密、Files 页面/动作权限、绑定有效以及 NAS ACL。超级管理员只绕过平台 RBAC，不绕过绑定、根目录边界或 NAS ACL。
- `FILES-FR-004`：根目录在界面显示“我的文件”，对应绑定身份访问的个人 SMB share 根；必须禁止切换共享、跳出根目录、借用户 ID 操作他人文件或通过链接/DFS 跳转到其他目标。
- `FILES-FR-005`：必须支持面包屑、上一级、前进/后退、刷新、按需展开目录树、列表/图标视图；展示名称、类型、大小和修改时间。目录树不得常驻占用文件浏览宽度，必须通过刷新按钮右侧的独立图标按钮打开尺寸受限的浮层，并在浮层内部滚动。文件列表必须以图标形状和语义颜色区分常见文档/PDF、表格、演示、图片、视频、音频、压缩包和代码类型，未知类型使用通用文件图标。默认文件夹优先、名称升序，支持当前目录名称筛选及列排序；目录大小显示“—”，不递归统计。文件和文件夹必须支持多选：普通点击单选，Ctrl/Cmd 点击切换单项，Shift 点击连续范围；每项提供触屏可用的显式选择控件。切换目录清除选择，多选状态显示准确数量。
- `FILES-FR-006`：必须支持文件选择与拖入多文件上传到固定目标目录；逐文件显示排队、上传、提交、成功、失败、取消状态及字节进度；失败可重试，成功文件不随整批失败而回滚。不允许静默覆盖，同名时用户可跳过或改名。
- `FILES-FR-007`：下载必须经授权后流式传输单个文件，浏览器原生保存；不得把大文件完整加载到 Web/Server 内存。不得在 URL 传递 JWT、SMB 密码或永久下载凭证。
- `FILES-FR-008`：具备新建目录权限的用户可以在当前目录新建单层文件夹；同名、非法名称和 NAS 拒绝必须明确提示。
- `FILES-FR-009`：必须区分未启用、未绑定、凭据失效、根目录不可达、NAS 离线、权限不足、路径失效、名称冲突、大小超限和空间不足；网络失败不能被误判为密码失效。
- `FILES-FR-010`：解绑、更换绑定、禁用/删除用户、会话失效、权限撤销后必须拒绝新的文件操作并尽力终止进行中的传输；旧绑定不能被后台任务继续使用。删除 Cove 用户不删除 NAS 账号和文件。
- `FILES-FR-011`：上传操作状态必须持久化，重启后可以识别中断、核对提交结果并清理属于该操作的临时文件；不声称支持关闭浏览器后继续上传。
- `FILES-FR-012`：具备独立动作权限的用户可以重命名当前 home 内的单个受支持文件或文件夹，目标必须仍在同一父目录且不得覆盖已有对象；可以在明确确认后删除一个或多个受支持文件或空文件夹。根目录、非空文件夹、上传临时文件、链接和越界路径不得删除。批量删除允许部分成功，响应和界面必须明确显示失败数量并刷新实际目录状态。

## 非功能需求

- `FILES-NFR-001`：SMB 密码必须采用独立 env 主密钥进行认证加密，数据库只存密文及解密元数据；密钥、凭据和原始 SMB 响应不得进入普通日志、审计、URL、Web 构建或浏览器持久化。
- `FILES-NFR-002`：必须校验路径与单个文件名，拒绝穿越、UNC/绝对路径注入、备用数据流、控制字符及跨共享跳转；生产链路使用 HTTPS，SMB 默认要求 SMB3 加密，禁止降级 SMB1/Guest。
- `FILES-NFR-003`：流式处理必须有背压、超时、并发和队列上限。初始建议：单文件 10 GiB、每用户 2 个活跃传输、全局 8 个、每用户 100 个待处理上传。数值可通过 env 调整，不是已经测得的容量。
- `FILES-NFR-004`：中英文、深浅主题、375/768/1440px、键盘访问、焦点可见和状态文本必须完整。右键和双击不能成为唯一入口。
- `FILES-NFR-007`：Files 页面不显示独立的“我的文件”标题和描述；文件管理器主体必须占满顶部栏以下的 main 可用高度并使用 flex 自适应，页面本身不得产生滚动，文件浏览区承担内部滚动。目录树浮层应采用协调的桌面/移动端宽度与受限高度，树内容在浮层内部滚动。传输入口必须位于搜索框右侧，以具有可访问名称的图标按钮呈现，并在弹窗中展示传输任务。
- `FILES-NFR-005`：绑定变更、新建文件夹、上传及下载结果、访问拒绝必须有脱敏审计和关联 ID；指标不得用用户名/完整路径作为高基数字段。
- `FILES-NFR-006`：目录枚举必须有数量/时间/内存上限，结果分页；数据不足时不得伪称全目录搜索完成。万级目录应验证可用，超限有明确提示。

## 已关闭的批准前提

1. 维护者已确认威联通 NAS `//NAS_HOST/home` 按 SMB 登录身份映射虚拟个人 home；协议/加密与双身份隔离进入实际验证。
2. 维护者在本轮明确批准完整方案与实施验证；采用独立主密钥认证加密、密钥分离保管与轮换方案。
3. 采用固定 smbprotocol 1.16.1 的独立 Python 协议进程；已实测真实 NAS 登录、双身份 home 隔离、流式读写、对象身份和原子不覆盖提交。

管理员统一管理绑定、单 NAS、禁止覆盖和非递归删除等均为本 Spec 的明确范围选择。
