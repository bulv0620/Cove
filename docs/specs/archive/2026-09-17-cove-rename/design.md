# 技术设计

## 统一命名

| 用途                          | 值            |
| ----------------------------- | ------------- |
| 产品、GitHub 仓库             | Cove          |
| 根包、镜像、默认 Compose 项目 | cove          |
| workspace scope               | @cove         |
| 版本变量                      | COVE_VERSION  |
| 浏览器 key / 内部事件前缀     | cove          |
| 上传临时前缀                  | .cove-upload- |
| 新安装数据库示例              | cove          |

## 浏览器状态

只读写 Cove 键，删除迁移映射和旧键访问。保留存储异常保护及当前页面内存回退；退出或 401 清除当前 token。既有浏览器旧状态不自动带入，用户重新登录和设置偏好。

## SMB 临时文件

Server 和 Python worker 都使用一个 Cove 前缀，大小写不敏感地识别保留名称。新建上传、目录过滤、rename/delete 保护与清理遵循同一规则。清理仍由持久化登记驱动并验证对象标识；不扫描或删除未知对象。原有其他前缀不再作为保留前缀特殊处理；本次不处理 NAS 中的旧对象。

## 工程与部署

所有 workspace 配置和 Docker 构建使用 Cove；Compose 只接受 COVE_VERSION，未设置时为 local。新安装、一般升级和回滚按长期 Docker 文档执行，移除本次改名专用的兼容迁移说明。真实环境文件、数据库和密钥不自动修改。

## 文档与历史

维护者明确要求归档 Spec 也统一品牌。历史文档中名称与命令按当前命名规范化，在 Specs 索引注明这不是重新执行历史验证；将已失效的临时证据绝对路径改为证据描述，不编造新路径。Git 历史不改写。

## 验证边界

单元测试验证单一 Cove 命名、存储错误路径、401 与退出、SMB 保留路径及对象标识校验。工程检查与镜像构建验证依赖和部署命名。界面布局沿用前轮已通过的检查；本轮验证不重做无关布局。真实 NAS 现场操作属于之后的部署工作。
