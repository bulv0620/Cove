# 单应用镜像部署

## 背景与问题

当前 Compose 使用独立 Web/Nginx 与 Server 镜像，MySQL 独立运行；migrate 和 bootstrap-admin 复用 Server 镜像。前端通过 Nginx 代理访问 `/api`。现有 Docker 配置已交付，但完整容器验收尚未完成。

维护者希望 NAS 部署只维护一个应用镜像，并由现有外部 MySQL 提供数据库。项目 Compose 不创建或管理 MySQL，只从 env 获取连接信息。本 Spec 由 NestJS 同时提供前端静态文件与 API。

## 目标

- 只构建一个包含前端、后端和 SMB 运行环境的应用镜像。
- Compose 只保留一个常驻应用容器，通过原有对外端口同时访问页面与 API。
- Compose 不创建数据库服务或数据卷，通过 `DATABASE_URL` 连接维护者管理的 MySQL。
- 保持身份、Files、迁移、初始化和数据库持久化行为兼容。

## 非目标

- 安装、升级、备份或监控外部 MySQL，改变 schema 或业务接口。
- CI/CD、镜像仓库发布、版本 tag 自动化和自动升级 NAS。
- 内置 HTTPS、证书申请、外部反向代理管理、水平扩容。
- 宣称尚未测试的 NAS 型号或 CPU 架构已获支持。

## 用户场景

### 首次部署

维护者先准备可从容器网络访问的兼容 MySQL，填写 `DATABASE_URL` 等环境变量并运行 Compose；迁移与 seed 成功后，单个应用容器启动。维护者显式初始化管理员，在同一地址打开页面并登录。

### 已有部署升级

维护者通过外部数据库的管理流程完成备份，保留独立密钥、旧配置和镜像，停止旧应用并切换新配置；新应用连接原数据库。用户和 SMB 绑定继续可用，不需要重新初始化数据库。

## 功能需求

- `IMG-FR-001`：必须通过一个多阶段 Dockerfile 构建唯一应用镜像，包含前端产物、后端、Prisma 运行与运维命令及 Python SMB 依赖；默认只启动一个 Node HTTP 服务，不运行 Nginx。
- `IMG-FR-002`：必须在同一端口提供页面、静态资源与 `/api`；前端页面直接访问和刷新必须可用。`/api` 及其子路径必须始终由 API 处理，包括不存在的 API 和失败响应，不能返回 SPA 页面。
- `IMG-FR-003`：静态服务必须仅暴露指定前端产物目录；缺失资源必须返回 404，不能返回 HTML 冒充脚本。SPA 兜底仅用于 GET/HEAD 页面导航，不得接管写请求。HTML 必须重新验证缓存；带内容哈希的资源可以长期缓存。
- `IMG-FR-004`：Compose 必须移除独立 web 和 mysql 服务及数据库卷，保留 server 服务名并改用统一 `home-ops:${HOME_OPS_VERSION:-local}` 镜像；`WEB_PORT` 默认仍为 8080，映射至应用 3000 端口。数据库只能通过必填 `DATABASE_URL` 配置。
- `IMG-FR-005`：migrate 与 bootstrap-admin 必须复用同一应用镜像，保留一次性命令、启动依赖和按服务注入环境变量的边界；migrate 必须直接连接外部数据库，迁移失败或数据库不可达必须阻止应用启动，管理员初始化必须保持显式执行。
- `IMG-FR-006`：必须保持同源认证、授权和 Files 流式传输语义，包括大小限制、背压、空闲超时、取消和 Secure 下载 cookie；移除 Nginx 不得引入整文件缓冲或固定传输总时长限制。
- `IMG-FR-007`：必须保持 Vite 开发服务器与独立 API 开发方式可用；开发后端缺少前端产物时仍可启动。统一生产镜像缺失入口文件时必须启动失败并给出不含密钥的错误。

## 非功能需求

- `IMG-NFR-001`：运行应用必须使用非 root 用户及现有 init/关闭机制，不要求特权、宿主机 CIFS 挂载或新增入站端口；镜像和公开静态目录不得包含真实环境文件、凭据或数据库备份。
- `IMG-NFR-002`：必须提供同时覆盖静态入口和现有 API 认证入口的健康检查，并准确说明其不代表持续数据库或 SMB 连通性。固定依赖和镜像版本，保留可执行的升级与回滚路径。
- `IMG-NFR-003`：必须记录容器和实际 NAS 验收证据；受阻项目明确标记未验证，不能将配置交付视为完整验收通过。

## 验收条件

- `IMG-AC-001`（FR-001/004/005）：连接预先准备的外部测试数据库后构建、启动成功；项目中只有 server 常驻，不创建 mysql 容器或数据卷；migrate 成功退出，bootstrap-admin 按需执行且重复执行不重置管理员。
- `IMG-AC-002`（FR-002/003/007）：首页、实际前端深层路由及刷新可用；JS/CSS MIME 正确；缺失资源 404；未知 API 和非 GET/HEAD 请求不返回 SPA HTML。独立开发可启动，生产缺失 index.html 时启动失败。
- `IMG-AC-003`（FR-002/006、NFR-001）：登录、强制改密及受保护 API 权限失败路径保持原契约；路径穿越、dotfile 和目录外文件请求不能读取文件；HTML 与哈希资源缓存头符合要求。
- `IMG-AC-004`（FR-006、NFR-001/003）：经 HTTPS 在实际 NAS 验证 SMB 绑定、浏览、上传、下载；传输内容校验一致。受控大文件持续传输超过 120 秒不被固定时限切断；观察内存和临时磁盘不随完整文件大小增长，并验证取消、空闲超时及超限失败。
- `IMG-AC-005`（FR-004/005、NFR-002）：从旧双镜像部署升级后用户和绑定保留；若旧部署使用 Compose MySQL，先将其数据迁移至外部数据库；迁移失败时应用不启动，重启后数据保留，保留旧镜像和配置可在兼容 schema 上完成回滚演练。
- `IMG-AC-006`（NFR-001/002/003）：容器非 root，健康检查覆盖页面和 API；镜像、HTTP 响应与日志的 canary secret 扫描通过。所有必需验收有环境、命令、结果和证据位置，长期文档更新后才能完成 Spec。

## 验收结论

- 维护者于 2026-09-17 验收并要求归档当前实现。
- `IMG-AC-001`、`IMG-AC-002`、`IMG-AC-003`、`IMG-AC-006` 已由本机 ARM64 clean-room、HTTP 契约、失败注入和 secret 扫描证据覆盖。
- `IMG-AC-004` 的实际威联通 HTTPS/SMB 大文件验证，以及 `IMG-AC-005` 的旧 Compose 数据库现场迁移与回滚，由维护者明确延期到首次生产部署；归档不表示这些环境特定路径已经验证，也不声明其他 NAS 架构已通过。
