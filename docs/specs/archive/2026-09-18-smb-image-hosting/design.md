# 技术设计

> 本设计已随 Spec 批准并进入实施；实现与验证进度以 `tasks.md` 为准。

## 设计摘要

```text
已登录浏览器
  │ JWT + images RBAC
  ▼
ImagesModule ──────────────────────────────────────► MySQL
  │  当前绑定的可重建索引 + 手动公开状态/publicId
  │
  └── SMB foundation ──► //NAS/home/Image Hosting/...

未登录请求
  │ GET /image/:publicId
  ▼
PublicImageController ─► ImagesModule 校验发布状态/所有者/绑定
                              └── SMB 流式读取 ──► image/*
```

NAS 是图片存在性、文件名、字节和 ACL 的事实源；MySQL 是“当前绑定下哪些对象由用户手动公开”的事实源。图床会扫描固定专用目录来发现图片，但新发现对象永远默认私有，不会因文件存在而自动生成公开链接。

## 组件与边界

- 新增 `ImagesModule`：独立 controller、service、DTO/输入解析、内容识别与图床状态管理。
- 从现有 Files 实现中提取最小 `SmbStorage` 基础边界：取得当前用户的密封凭据与绑定版本、受控相对路径、mkdir/stat/open-read/open-write/rename-no-replace/delete 以及全局并发配额。
- `FilesModule` 和 `ImagesModule` 可依赖 SMB 基础能力，但 Images 不通过调用面向用户的 `/api/files` 端点实现。
- Web 导航将图床放在 Infrastructure 分组中，与 Files 并列，不属于 Applications。
- 公开 controller 不使用 JWT 守卫，只接受 `/image/:publicId` 中的公开 ID；不接受相对路径、用户 ID、MIME 或下载文件名。
- 对账器枚举当前绑定的固定图床根目录，以稳定 SMB 对象身份为优先关联键。新文件建立私有索引，缺失文件撤销链接，目录内重命名在对象身份可证明时更新路径。

## 数据模型

建议新增 `ImageAsset`：

- `id`：内部 UUID。
- `publicId`：可空；公开时生成唯一、高熵且 URL-safe 的随机标识，至少 128 bit 随机性。关闭公开时将其永久撤销，不再使用。
- `userId`：所有者，删除用户时记录级联删除；删除用户前对 NAS 字节的处置需与生命周期决策一致。
- `bindingVersion` 与 `configFingerprint`：防止换绑后使用新身份读取旧路径。
- `relativePath`：受控内部路径，不对客户端返回。
- `displayName`：由当前 SMB 文件名派生，目录内重命名对账后更新。
- `mediaType`、`extension`、`sizeBytes`、`sha256`：发布时确认的元数据。
- `state`：`UPLOADING | COMMITTING | PRIVATE | PUBLIC | REVOKED | MISSING | CLEANUP_PENDING | FAILED`。
- `objectId`、`tempPath`、`leaseExpiresAt`、`errorCode`：用于未知提交与清理恢复。
- `createdAt`、`publicAt`、`revokedAt`、`lastSeenAt`、`updatedAt`。

建议另建不可复活的 `ImagePublicGrant`/tombstone 记录保存历史 public ID 及撤销时间，避免关闭后再开启意外恢复旧 URL。绑定版本变化时批量撤销该用户当前全部 grant，但不删除 NAS 图片。

不复用现有 `FileOperation` 表来表示长期图片记录；两者生命周期和对外语义不同。实现评审时可决定是否另建操作表，但不得降低 Spec 中的恢复要求。

## API 契约

建议的最小 API：

- `GET /api/images`：当前用户图片分页列表。
- `POST /api/images/uploads`：预留图片记录与上传操作，返回上传 ID。
- `PUT /api/images/uploads/:id/content`：上传内容流并在验证、原子提交后发布。
- `GET /api/images/uploads/:id`：查询操作状态。
- `DELETE /api/images/uploads/:id`：取消未完成上传。
- `PATCH /api/images/:id/visibility`：所有者开启或关闭公开访问；每次开启生成新 public ID。
- `DELETE /api/images/:id`：撤销并请求清理所有者的图片。
- `GET /image/:publicId`：无登录读取已手动公开的图片。

管理 API 只返图片业务 ID、文件名、大小、格式、状态、时间和由 Server 组装的公开 URL，不返图床内部目录、SMB 路径、绑定版本或配置指纹。

## 内容识别与上传流程

1. Server 预留内部记录和安全存储名，固定当前绑定版本；只有上传请求选择公开时才预留 public ID。
2. SMB 专用目录按需逐层创建，对既有非目录对象、链接或不可信属性拒绝继续。
3. 上传流写入唯一临时对象，同时计数、计算 SHA-256 并只缓冲足以识别格式的有界前缀；不缓存完整图片。
4. 检查文件签名、声明大小/实际大小、允许格式和最小结构完整性；失败则关闭并登记清理临时对象。
5. 以 SMB 不覆盖 rename 提交到正式路径，持久化对象标识与精确字节数，然后根据用户选择标记 `PRIVATE` 或 `PUBLIC`。
6. 只有 `PUBLIC` 记录的当前 public grant 可由 `/image/:publicId` 读取。

仅文件签名识别不能排除所有多重格式文件。实现前必须为每个批准格式明确有界解析/结构校验方案，或缩小首期格式集合。

## 公开读取与缓存

- public lookup 先按 `publicId + PUBLIC` 查询，再校验用户可用性、SMB 配置指纹、绑定版本和当前对象身份，最后使用密封凭据流式打开登记对象。
- 对不存在、撤销、用户不可用、解绑和换绑使用相同的对外不可用响应。SMB 暂时超时/离线可返回统一 `503` 与有界 `Retry-After`，但不返回原因细节。
- 响应只使用数据库中经发布确认的 MIME，并设置 `nosniff`、限制性 CSP、不反射原文件名的 `Content-Disposition: inline`。
- 在撤销优先的默认方案中，建议 `Cache-Control: public, max-age=60, must-revalidate`；最终数值需要在 Spec 批准前确认。
- ETag 可由已保存的安全内容摘要生成，不包含路径或用户信息。首期不承诺 HTTP Range；若验收需要大型动图的 Range，需先扩展 Spec。

## 页面与交互设计

图床页面使用 Cove 现有色彩、字体、圆角、Lucide 图标和深浅主题，不引入新的品牌风格。信息架构以图片内容为主，每个页面只保留一个主操作“上传图片”。

### 桌面结构

```text
图床                                      [上传图片]
Image Hosting/ · 上次同步 10:32       [在 Files 中打开]

[搜索文件名…]  [全部 | 私有 | 已公开]  [最新修改 ⌄]  [刷新]

┌──────────────────┐  ┌──────────────────┐  ┌──────────────────┐
│    图片缩略图      │  │    图片缩略图      │  │    图片缩略图      │
│ [私有]       [选择] │  │ [已公开]     [选择] │  │ [待清理]     [选择] │
├──────────────────┤  ├──────────────────┤  ├──────────────────┤
│ photo.jpg        │  │ diagram.png      │  │ old.webp         │
│ 2.4 MB · 9 月 18 日 │  │ /image/Ab3… [复制] │  │ 文件清理失败 [重试]│
│ [开启公开链接]   │  │ [管理公开链接]   │  │ [查看详情]         │
└──────────────────┘  └──────────────────┘  └──────────────────┘
```

- 顶部标题区显示固定目录 `Image Hosting/`、最近对账时间和“在 Files 中打开”次要入口。
- 工具栏包含文件名搜索、全部/私有/已公开筛选、修改时间/名称/大小排序与手动刷新。不放置与首期无关的统计卡。
- 图片卡使用固定宽高比预留布局，避免图片加载导致页面跳动。卡片同时使用文字标签和语义颜色显示“私有”、“已公开”、“待清理”等状态。
- 私有图片显示明确的“开启公开链接”按钮，不显示空链接框。已公开图片显示截断的 `/image/{publicId}` 和独立复制按钮；复制时实际写入包含当前 origin 的完整 URL。
- 卡片点击打开详情弹窗，但公开开关、复制和选择按钮有独立点击区，不触发卡片打开。关键操作不依赖 hover 或右键。

### 上传弹窗

- 主按钮打开带明确边界的拖放区，同时提供“选择图片”按钮作为键盘/触屏替代方式。
- 文件队列显示文件名、大小、格式校验、逐项进度、取消和失败重试；错误位于对应文件附近。
- 队列上方提供带可见标签的“上传后开启公开链接”开关，默认关闭。开启后显示辅助文字“拿到链接的人无需登录即可查看”。
- 弹窗关闭不得中断已开始上传且不给出说明；离开页面时沿用 Files 传输队列的可见性和取消语义。

### 图片详情与公开权限

- 详情弹窗显示较大预览、当前文件名、格式、字节数、SMB 修改时间和公开状态。私有预览使用需登录的预览端点，不为预览偷偷生成公开链接。
- 开启公开后，在状态区原地出现只读完整链接、“复制链接”和“复制 Markdown”；通过 `aria-live="polite"` 宣告创建成功和复制成功。
- 关闭公开前显示确认：明确说明现有链接将永久失效，之后重新开启会生成新链接。确认按钮使用危险语义，关闭后保留弹窗和焦点语境。
- 删除图片与关闭链接是两个不同操作；删除位于弹窗底部的危险区，需要单独确认。

### 响应式与可访问性

- 1440px 下网格根据可用宽度显示 4–6 列，768px 显示 2–3 列，375px 显示单列；所有宽度不产生水平滚动。
- 移动端工具栏换行为搜索行与筛选行，上传按钮保持首屏可见。卡片上仍显示截断链接和至少 44px 的复制按钮，不把操作只放在悬停层。
- 网格使用分页或虚拟化、非首屏图片懒加载、固定 `aspect-ratio` 和骨架屏。加载超过 300ms 必须显示反馈，不允许空白容器。
- 所有按钮/开关有可见文字或可访问名称，触摸区至少 44×44px，焦点环可见，Tab 顺序与视觉顺序一致。弹窗捕获焦点、Esc 关闭并在关闭后将焦点返回触发元素。
- 动效仅使用 150–250ms 的透明度/位移状态反馈，不改变布局尺寸，并遵守 `prefers-reduced-motion`。

### 空状态与故障

- 未绑定 SMB：显示图床依赖 SMB 的原因；有绑定管理权时给出可执行入口，无权时提示联系管理员。
- 目录不存在且无图片：显示“上传第一张图片”，不需要用户手动建目录。
- 对账进行中：保留已有内容，工具栏显示非阻塞“正在同步 Image Hosting/”；发现外部变更后以简短状态消息说明新增/失效数量。
- NAS 离线或超时：保留上次已知列表但明确标记为可能过期，禁用会产生误导的公开/删除操作，并提供重试。

## 状态与失败恢复

- 过期 `UPLOADING` 记录转为 `FAILED` 并登记临时文件清理。
- 过期 `COMMITTING` 记录进入核对；仅当已登记的对象身份和精确长度匹配时可按原用户选择恢复为 `PRIVATE` 或 `PUBLIC`。
- 删除在数据库中先从 `PRIVATE`/`PUBLIC` 原子转为 `REVOKED`，之后尝试 SMB 删除。成功后可保留短期 tombstone 后清除；失败转为 `CLEANUP_PENDING`。
- 自动清理只能操作该记录的受控路径与对象标识，不按文件名前缀批量删除未知 NAS 对象。
- 绑定已删除或替换后，不得使用新凭据清理旧路径。待清理记录保留给维护者核对，不假报字节已删除。

## 安全与权限

- 建议资源码 `infra.images`，权限码 `infra.images.page`、`infra.images.upload`、`infra.images.publish`、`infra.images.delete`。复制链接是已公开数据的本地交互，不单独建权限。
- 内置 administrator 按现有规则获得未来权限；自定义角色需要显式授予。
- 公开读取不使用用户会话，安全性依赖高熵 ID、最小响应差异、速率/并发限制、安全响应头与精确的发布状态。
- 完整威胁模型至少覆盖：公开 ID 枚举、热链流量放大、SMB 连接耗尽、格式欺骗/多重格式、响应嗅探、缓存污染、路径穿越、换绑越界、删除竞态、日志泄露与公开服务对 NAS 的间接 DoS。

## 本地开发与生产部署

- 复用现有 SMB 目标、凭据密钥、Python helper 和 TCP 445 连通性配置。
- 新增的单图上限、公开读取并发/频率、超时和缓存 TTL 使用有边界的 env 配置，非法值阻止 Server 启动。
- Cove 只保证在当前应用 origin 上提供 `/image/{publicId}`。生产非 loopback 访问建议 HTTPS；域名、TLS、公网路由部署环境自行决定，不属于本 Spec 的功能或验收范围。

## 迁移与兼容性

- Prisma 只新增图片业务表/枚举和关联，不改写已有 `SmbBinding`、`FileOperation` 或 NAS 文件。
- seed 幂等增加图床资源与权限；不为自定义角色自动授权。
- 回滚应先停止新上传，将全部公开记录撤销或保留可运行旧版本；直接回滚到不支持 Images 的应用会使公开 URL 不可用，但不自动删除 NAS 文件。

## 可观测性

- 审计记录上传预留/发布结果、撤销、清理和越权管理尝试；高频成功的公开 GET 使用聚合指标而非逐条写审计表。
- 指标至少包含公开 GET 成功/不可用/上游错误/限流数、流式字节数、延迟、活跃 SMB 读取和待清理数，不使用高基数标签。
- 公开响应和内部日志共享可追踪 request ID，但不向匿名访客返回内部错误、SMB 状态或所有者信息。

## 备选方案

- **直接暴露 SMB 路径**：不采用。会泄露结构，无法稳定撤销，且容易在换绑时越权。
- **只用文件名作为公开键**：不采用。可枚举、有冲突并泄露原文件名。
- **上传后复制到 Server 本地或对象存储**：不采用。与本次 SMB 作为字节事实源的目标不符。
- **只复用 Files 下载票据**：不采用。票据是短期、一次性、附件下载，不符合长期匿名内联图片的语义。
