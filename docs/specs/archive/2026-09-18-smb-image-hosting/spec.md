# SMB 图床

## 背景与问题

Cove 已实现每用户 SMB 绑定、个人 `home` 文件访问、流式上传下载、路径安全和权限守卫，但尚未实现图床、预览、分享或外链。本次变更将 SMB 视为图床及后续个人文件类功能的存储基础，而不在 Cove 本地磁盘或 MySQL 中保存第二份图片字节。

图床是 Infrastructure 下与 Files 并列的独立功能入口。其核心问题是：已绑定 SMB 的 Cove 用户需要将图片上传到自己的专用目录，在默认私有与手动公开之间管理每张图片，并为已公开图片获得可直接加载的稳定链接。

## 目标

- 已绑定有效 SMB 账号的用户可上传、查看、设置公开性、复制链接和删除自己的图片。
- 图片原始字节必须存储在该 SMB 身份的个人 `home` 下的 Cove 专用目录中。
- 每张由用户手动开启公开访问的图片必须获得不暴露 NAS 结构、用户名或 SMB 凭据的公开链接。
- 重新绑定或换绑到已存在图床目录的 SMB 账号时，必须能重新发现其中的图片，但不恢复任何旧公开链接。
- 绑定更换、用户禁用、图片删除、NAS 离线等状态必须有可预期且不越权的行为。
- 设计可被后续 Notes 等模块复用，但本期不预先实现这些业务功能。

## 非目标

- 不提供面向用户的图片编辑、裁剪、压缩、格式转换、响应式多尺寸或 EXIF 清理；页面网格所需的可重建私有缩略图缓存除外。
- 不提供相册、批量对外分享、访问密码、到期时间、一次性链接或访客上传。
- 不引入 CDN、对象存储、本地挂载、第二份完整文件或全量文件索引。
- 不支持 SVG、HTML 或任意文件托管；不以扩展名作为内容安全判断。
- 不允许用户选择 NAS 主机、共享、绝对路径或图床根目录。
- 不屏蔽 Files 对图床目录的正常浏览、上传、重命名或删除；但不将图床目录以外的普通图片自动纳入图床。
- 不实现通用的跨模块 SMB 文件 SDK；只提取本期实际需要的共享能力。

## 术语与建议默认值

- **图床根目录**：相对于当前 SMB 身份 `home` 的固定可见普通目录 `Image Hosting/`。
- **图片事实**：图床根目录中通过内容校验的图片文件。SMB 目录是图片存在性、文件名和字节的事实源。
- **图片记录**：MySQL 中的可重建业务元数据，保存当前 Cove 用户/绑定下对应文件的路径、对象身份、安全 MIME、字节数、内容摘要和公开状态；不保存图片字节。
- **公开链接**：用户手动开启后生成、无需 Cove 登录即可使用的同源 `/image/{publicId}` URL；不包含 JWT、SMB 路径、原文件名或用户标识。
- **首期格式**：JPEG、PNG、WebP、GIF 和 AVIF；通过文件签名识别，不只信任浏览器上报的 MIME 或扩展名。
- **单图上限**：25 MiB，可通过 Server env 在受控范围内调整。
- **缩略图缓存**：`Image Hosting/.cove-cache/thumbnails/` 中的小尺寸私有派生文件，可删除并按需重建；不是原图或公开链接的事实源。

## 用户场景

### 上传并复制外链

用户拥有图床页面与上传权限，且 SMB 绑定有效。用户选择或拖入一张或多张支持的图片，可在上传前选择是否公开；系统将每张图片流式写入可见专用目录。上传成功后显示预览、文件名、大小、时间与公开状态；只有公开图片显示可复制的直链。

### 重新绑定已有目录

用户解绑后再绑定，或换绑到另一个已有图床目录的 SMB 账号。图床页面重新枚举与校验目录中的图片，并将它们作为当前绑定下的私有图片展示。旧绑定下的公开 ID 不恢复；需要链接时必须由用户重新开启公开访问并生成新 ID。

### 外部页面访问

访客在不登录 Cove 的情况下请求公开链接。链接有效时，Server 以该图片所属的 SMB 绑定流式读取文件并返回安全的图片响应；链接不存在、已撤销或所属用户不可用时，对外统一表现为不可用，不泄露账号或 NAS 状态。

### 删除图片

用户在明确确认后删除自己的一张或多张图片。系统先使外链失效，再尝试删除 SMB 文件；部分失败必须保留可追踪状态并允许重试清理，不得将删除失败的字节恢复为公开状态。

## 功能需求

- `IMAGES-FR-001`：系统必须在 Infrastructure 导航分组中提供与 Files 并列的独立图床页面与资源，至少包含页面、上传、管理公开状态和删除动作权限。服务端必须独立执行授权；超级管理员仍需要有效的自有 SMB 绑定。
- `IMAGES-FR-002`：图床必须只使用当前 Cove 用户的 SMB 绑定，并在其个人 `home` 下按需创建固定的可见图床根目录。该目录是普通用户文件目录，Files 必须可正常浏览和操作。客户端不得指定根路径、NAS 目标、共享或其他用户。
- `IMAGES-FR-003`：用户必须可以通过文件选择和拖放批量上传支持的图片，在上传时选择是否公开，并获得逐文件的排队、上传、提交、成功、失败和取消状态。每次打开上传流程时，公开选项都必须默认关闭，不记住上次开启状态。上传必须流式写入独占临时文件并以不覆盖的原子重命名提交。
- `IMAGES-FR-004`：系统必须根据实际文件签名确定允许的图片格式与响应 MIME，并拒绝格式不符、超限、截断、多重格式歧义及包含主动内容的输入。不得仅依赖扩展名或客户端 MIME。
- `IMAGES-FR-005`：图片默认不公开。用户可在上传时选择公开，也可对已有图片开启或关闭公开访问。每次从非公开切换为公开时必须生成至少 128 bit 随机性的新公开 ID；已撤销 ID 不得恢复。公开 URL 固定为同源 `/image/{publicId}`，不暴露所有者、文件名或 SMB 路径。
- `IMAGES-FR-006`：图床页面必须枚举当前绑定的图床根目录，列出其中通过验证的图片，支持分页、预览、文件名、格式、大小、修改时间、公开状态、复制直链和 Markdown 片段。新发现的文件必须默认私有；不得因同名或目录中存在旧文件而恢复旧公开 ID。
- `IMAGES-FR-007`：公开图片读取路由 `/image/{publicId}` 必须允许无登录访问，从 SMB 向 HTTP 响应流式传输字节，返回固定的安全 `Content-Type`、`X-Content-Type-Options: nosniff`、CSP 及短缓存/必须重验证的缓存头，不以附件下载。Cove 只提供路由和访问控制，不负责域名、TLS、公网暴露、穿透或 CDN。未知、撤销和所有者不可用必须使用统一对外错误，NAS 暂时故障可区分为可重试的服务错误，但不泄露内部原因。
- `IMAGES-FR-008`：只有所有者可以删除自己的图片。删除必须先不可逆地撤销公开访问，再删除对应 SMB 文件；字节清理失败时必须持久化待清理状态并允许安全重试。
- `IMAGES-FR-009`：任何会更改 SMB 绑定版本的保存、换绑或解绑，以及用户禁用或删除，必须立即使该用户的全部旧公开 ID 永久失效。重新绑定同一账号或换绑到存在同名路径的账号都不得恢复旧 ID；但图床必须重新枚举新绑定下的图床目录，将其图片作为私有图片展示，允许用户手动生成新公开 ID。
- `IMAGES-FR-010`：图床必须在打开页面、手动刷新以及公开读取前的必要校验中，将 SMB 目录实际对象与 MySQL 记录对账。Files 中新增的合法图片以私有状态出现；删除的文件必须使公开链接失效；同一 SMB 对象在图床根目录内重命名时应保留其公开状态。若 NAS 不能提供稳定对象身份，必须采用更保守的失效并重新发现为私有，不得仅按同名文件保留公开链接。
- `IMAGES-FR-011`：上传、公开状态变更、公开读取和删除必须定义重启、超时、部分失败与未知提交结果的恢复规则；不得仅凭同名文件存在就声称发布成功。
- `IMAGES-FR-012`：图床必须复用 SMB 配置、凭据密封、连接并发限制、路径政策和流式适配能力，但图床业务状态、公开链接和权限必须属于独立模块，不得绕过现有 SMB 安全边界。

## 非功能需求

- `IMAGES-NFR-001`：上传和公开读取必须全程流式化并有背压，Server/Web 内存或磁盘不得保存第二份完整图片。必须共享已有 SMB 全局进程上限，并对公开读取增加单 IP 和全局并发/频率保护。
- `IMAGES-NFR-002`：公开 ID、内部存储名和临时名不得可猜测；任何 API、日志、审计、缓存键或错误响应都不得包含 SMB 凭据、密文、原始 SMB 响应或不必要的内部路径。
- `IMAGES-NFR-003`：Cove 必须防止路径穿越、链接/DFS/reparse point 越界、文件类型嗅探、缓存混淆、枚举公开 ID 和通过错误差异探测用户或 NAS 状态。对非 loopback 环境的安全部署必须建议 HTTPS，但 Cove 不在本期配置外部访问链路。
- `IMAGES-NFR-004`：图床页面必须支持中英文、深浅主题、375/768/1440px、键盘操作、可见焦点、可访问的进度/失败状态和非仅颜色的状态区分。
- `IMAGES-NFR-005`：上传、发布、复制链接以外的管理变更、公开读取拒绝/限流和删除结果必须留下脱敏审计或可观测计数；指标不得使用公开 ID、用户名或完整路径作为高基数标签。
- `IMAGES-NFR-006`：必须明确区分公开链接的长期缓存语义与立即撤销目标；实现不得同时声称“强长缓存”和“立即全网失效”。
- `IMAGES-NFR-007`：图片网格必须使用有界尺寸的非公开缩略图，不得为列表预览批量传输原图。缩略图只能存放在 `Image Hosting/.cove-cache/thumbnails/`，必须可删除、可重建、不被目录对账当作原图，且不得通过 `/image/{publicId}` 公开。

## 验收结论

- 维护者于 2026-09-18 验收当前实现并要求归档。
- 本地自动化、图片格式/安全语料、空库迁移、seed 幂等、生产构建与 Linux arm64 镜像构建证据通过；当前开发数据库的增量迁移已实际应用并确认 schema 最新。
